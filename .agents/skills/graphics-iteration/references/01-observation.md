# 观察面与场景编排

图形迭代先固定“看什么”：同一工程、同一场景、同一机位/光向/后处理条件，才有可比的数字。

## 一、观察面的组成

- **工程与场景**：固定验证工程与场景；默认场景由项目状态文件或启动参数决定，迭代期间保持一致。
- **视图**：Game 视图反映最终画面，Scene 视图反映编辑器视角；两路画面分别采集、分别命名。
- **机位与光向**：用观察 rig 或预设表组织；每条预设含时间点、相机位姿与可见性。
- **后处理**：中性面（关闭 bloom/描边等效果）与成片面分开出图，分别判读。

## 二、观察装配

- 把相机、光源、环境体与观察物收进 rig 子树；可见性预设按子树内层级路径寻址。
- 预设表每条为 `{name, time, visibility[]}`；`time` 是 clip 秒数；纯 visibility 预设（无动画组件）同样合法。
- 用观察预设的查询与应用接口；应用结果返回的分发帧号作为采帧锚点。
- 一个场景编排一个主 rig；存在多个 rig 时显式指定实体。
- 路径命中但缺少渲染组件、路径未命中时，把结果标注为未应用，并通过预设明细核对编排。

## 三、光向矩阵与 clip 标定

- 每个机位分配一个时间窗，窗内相机键保持同值；窗内每秒一个光向键，预设 `time` 锚在光键点上。
  锚点落在键间会把光向摆斜，实测时以键点对齐。
- 相机与灯的 look-at 键用脚本按项目数学约定推导；先用既有 clip 的已知“看向场景”键做标定校验，再生成新键。
- 灯实体局部 +Z 为传播方向；`light_quat` 与相机 look-at 使用同一公式，eye 取光源虚拟位、目标取受照体。
  着色侧对 L 的取反在渲染提取点处理，观察编排直接使用同一坐标系。
- **工作点真源是 clip 键**：预设的机位/灯光/曝光由描述 JSON 重产的 clip 驱动；场景描述文件只等于 t=0 的键。
  修改描述 JSON → 重产 clip → 走资产导入。
- **光向效果定量判读**：背景抠角色掩码 → 逐张算左右半区亮度比与角色均值亮度。判据：同行 left/right
  比值互镜像且方向相反、front 行最亮且左右近似对称、正面机位行 back 最暗（逆光入影）、背面机位行
  back 最亮（背部受光）。实现复用现有 ROI 统计脚本。

## 四、摆相机

脚本化摆机位使用组件写入，确定性最好：

1. **寻址**：从日志或场景树查编辑器相机实体 id；该实体可能隐藏于层级视图，按 id 直查、直写。
2. **写位姿**：通过组件写接口设置相机实体的位置与旋转；四元数为 `[x,y,z,w]`，
   恒等为 `[0,0,0,1]`，前向为局部 +Z。
3. **复核**：写入后读回位姿，确认与预期逐分量一致；出图前用同一相机状态。

交互面按编辑器的聚焦、环视、飞行操作使用；脚本复现时沿用同一机位与 FOV 口径。
