# 出图与留档

判读的第一步是拿到真实输出帧并保持同一口径。采集契约、缺帧判定与参数细节由项目采集工具负责。

## 一、离屏采真实帧

- 用项目提供的离屏采集入口：起编辑器或运行时、订阅帧通道、按 seq 窗口落裸帧与 meta。
- **视图分开**：Game 视图与 Scene 视图分别采集；缺省过滤可能把两路画面混在同一 seq。
- 可执行文件与工作目录用绝对路径；输出目录先创建，脚本按该路径写日志与帧文件。
- `--want-seq` 留足锚点余量：帧通道不缓冲订阅前帧，锚点过低会让整窗冲过、保存 0 帧。
- 帧数给足余量，让采集结束后拆 server 时仍能拿到完整日志。
- 用显式 token 拉起会话；离屏采帧时跳过浏览器 UI 链，减少无关依赖。
- 产物：`frame<seq>.bin`（裸像素）+ `meta.json`（seq/尺寸/格式）+ `engine.log`。
- 采集结束确认脚本拉起的编辑器已退出。

## 二、矩阵出图

- 有专用观察矩阵时，用一条命令跑完：起离屏编辑器 → 加载场景 → 可选后处理 override → 逐 leg 出图 →
  补拍特写 → 逐 leg ROI 指标 → 汇总 JSON + contact sheet。每轮重跑同一口径做前后对比。
- **中性面与成片面**分别出图：中性面临时关闭 bloom/描边等效果，并读回原值；成片面保留场景原样。
  中性 override 把强度和阈值一起归零，结果对打包顺序不敏感。
- 每轮显式给 `--out temp/<任务名>`；`temp/` 是工作区临时目录，不入库。产物含 capture PNG、`eval_metrics.json`、
  `contact_sheet.png` 与日志。
- 场景或预设数量变化后，先核对 ROI 与 contact sheet 口径，再采信数字；脚本的 WARN 作为核对提示。

## 三、单 trial 参数化出图

- 单 trial 做「应用参数 → 逐 leg 出图 → 指标 → 还原」，供闭环搜索和手工验参使用。
- Volume/灯光覆盖在每次 seek 之后重新落，capture 前复读；值被动画写回时整 trial 失败，
  保证搜到的参数就是画面实际参数。
- 材质补丁只改指定下标，其余分量读回保留；写盘后按字节快照还原并校验，采后核对 `git status`。
- 单 trial 只采指定 leg；验收与回归使用全量判读面。
- 估预算时按单 leg 的启动+采集时间累加，搜索预算据此设置。

## 四、裸帧转 PNG

- 按帧格式码解码：RGBA8 的字节序为 R,G,B,A，紧凑行序、顶行在前；BGRA8 交换通道后写入。
- 尺寸从同名 meta 读取；散 bin 用 `--width/--height` 显式给。
- 细节判读用 `--crop x,y,w,h` 裁原生分辨率局部，再用 `--zoom N` 最近邻放大。
- 读图上限按长边像素计算：长边超过约 1500–2000px 会被内部降采样，1px 纹理与小字先裁剪。
- 统一走无损转换脚本；截屏、JPEG 中转与有损缩放会改变颜色与细节。

## 五、改前改后对比与留档

- **指标对比**：配对两份 metrics JSON，输出逐 leg 分位差、亮度比、clip、哈希相同数、缺 leg、超限项与分组汇总。
  先看对比 JSON，再回到 contact sheet 与原图目检。
- **逐像素对拍**：行为中性/回归按 seq 配对判 IDENTICAL/DIFF/SKIP，缺帧按失败处理；哈希比较用于冻结自检。
- **基线与证据目录**：证据目录命名 `temp/<任务名>[_neutral|_scene]`，每轮一个目录，保留基线目录到收口。
- **产物新鲜度**：判读前确认二进制构建时间晚于相关源码提交；运行日志包含预期布点，缺布点行说明二进制过旧。
