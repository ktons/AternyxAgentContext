# 设计与多阶段规划

把重要设计选型、多阶段方案和依赖整理为可执行、可验收的计划；本 skill 不修改生产代码。普通局部修改遵循 `AGENTS.md`。

## 授权与范围

- 只读摸底、评估在会话回答，确认核心意图，技术选型后整理为 roadmap；执行须明确指示。
- 整理方案时贴合主流，重要新选择给候选、权衡和推荐，最终以用户选择及要求为准。
- 任务范围由用户指定，规划时涉及其他模块的小修小补可纳入迭代计划。

## 规划路径

1. **需求与范围**：列目标、边界、约束和验收，重要歧义向用户详细说明。
2. **定向勘察**：架构入口 → 模块文档 → 必要签名/布局；记录 HEAD、工作区状态、勘察方式与 file:line。
   独立域可派只读 agent，只查任务缺口并复用结论，不为填模板做全库审计。
3. **设计与依赖**：每需求写“现状差距 → 证据 → 改动面”，说明目标接口、生命周期、数据归属、
   依赖顺序和分阶段依据。借鉴成熟引擎概念，抽象需服务于当前目标与可见演进，避免投机泛化。
4. **任务与验收**：任务是可独立编译验收的完整增量，给文档入口、文件/符号/先例、目标目录、target、
   suite 命令和必要行为证据。约 40 分钟实现量只作拆分估计，不当质量判据。
5. **落位与移交**：讨论在会话进行，长草稿放 `docs/temp/<主题>.md`，正式计划自包含、不引用草稿。
6. **roadmap模板**：roadmap 用下方模板，先确认当前为空或用户明确替换/追加。

与本期相关时检查以下类别，逐条写处置，不要求每期全扫：

| 类别 | 典型线索 |
|---|---|
| 硬编码/重复约定 | 相机参数、帧长、路径、键码多处手抄 |
| 耦合/依赖边 | 反向依赖、接口边界不清、CMake 接线未登记 |
| 数据/生命周期 | 单视口字段阻塞多视口、生产链不调用回调 |
| 死配置/资产漂移 | 零调用 API、无效开关、源资产缺组件、schema 与实现不符 |

## 落位模板

- [计划模板](templates/plan-template.md)：静态需求、设计、验收与风险；代码锚点注明快照，行号漂移不是设计冲突。
- [roadmap 模板](templates/roadmap-template.md)：唯一任务状态、决策和执行记录，不为小任务生成空表。
- 执行分支只登记当前或用户指定值，集成目标未约定填“未指定”。本地提交按 AGENTS，禁止 push。
