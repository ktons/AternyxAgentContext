# 设计与多阶段规划

把重要设计选型、多阶段方案和依赖整理为可执行、可验收的计划。本技能产出计划与文档；实施按后续的执行授权推进。普通局部修改按工作区规则处理。

## 授权与范围

- 先只读摸底并在会话中给出评估，确认核心意图与技术选型，再整理为 roadmap；收到明确执行指令后进入实施。
- 方案贴合主流做法；重要的新选择给出候选、权衡与推荐，最终按用户的选择和要求落定。
- 范围按用户指定整理；规划中发现的相邻模块小修小补可纳入迭代计划。

## 规划路径

1. **需求与范围**：列出目标、边界、约束和验收标准；遇到重要歧义先向用户说明并确认。
2. **定向勘察**：按架构入口 → 模块文档 → 必要签名与布局的顺序阅读；记录 HEAD、工作区状态、勘察方式与 file:line。
   独立领域可派只读 agent，只查任务缺口并复用结论。
3. **设计与依赖**：每项需求写“现状差距 → 证据 → 改动面”，说明目标接口、生命周期、数据归属、依赖顺序和分阶段依据。
   借鉴成熟引擎概念，抽象服务于当前目标与可见演进。
4. **任务与验收**：把任务拆成可独立编译验收的完整增量，给出文档入口、文件/符号/先例、目标目录、构建目标、测试命令和必要的行为证据。
   约 40 分钟实现量只作拆分估计，质量以验收结果判断。
5. **落位与移交**：讨论留在会话，长草稿放 `docs/temp/<主题>.md`，正式计划自包含，执行所需结论直接内联。
6. **roadmap 模板**：roadmap 使用下方模板；初始化前确认当前为空或用户明确要求替换/追加。

与本期相关时检查以下类别，逐条写处置；与本期无关的类别直接略过：

| 类别 | 典型线索 |
|---|---|
| 硬编码/重复约定 | 相机参数、帧长、路径、键码多处手抄 |
| 耦合/依赖边 | 反向依赖、接口边界不清、构建接线未登记 |
| 数据/生命周期 | 单视口字段阻塞多视口、生产链未调用回调 |
| 死配置/资产漂移 | 零调用 API、无效开关、源资产缺组件、schema 与实现不符 |

## 落位模板

- [计划模板](templates/plan-template.md)：静态需求、设计、验收与风险；代码锚点注明快照，行号漂移以代码为准。
- [roadmap 模板](templates/roadmap-template.md)：唯一任务状态、决策和执行记录；小任务直接用表内一行记录。
- 执行分支登记当前值或用户指定值，集成目标未约定时填“未指定”。本地提交按工作区规则执行，远端操作由用户发起。
