# 文档编写与维护

本技能是模块文档写作的唯一规范，并约定设计文档、开发文档等一次性文档的落位与写法。
编写模块文档时先从 `docs/overview-architecture.md` 定位所属模块，再读模块文档，以必要源码核对当前事实。

## 文档类型与落位

| 类型 | 用途 | 位置 | 生命周期 | 模板 |
|---|---|---|---|---|
| 模块文档 | 维护模块当前事实 | `docs/modules/` | 永久，随代码同步 | [模块入口](templates/module-overview.md)、[主题文档](templates/module-topic.md) |
| 设计文档 | 记录一次设计的目标、选型与方案 | `docs/design/` | 一次性产物 | [设计文档](templates/design-doc.md) |
| 开发文档 | 记录一次面向开发者的操作说明 | `docs/dev/` | 一次性产物 | [开发文档](templates/dev-doc.md) |
| 会话总结 | 归纳一次讨论、分析或结论 | `docs/temp/` | 一次性产物 | 按内容组织 |
| roadmap 与迭代计划 | 当前迭代的任务状态、决策与执行 | `docs/iteration/` | 迭代收口清空 | [roadmap](templates/roadmap.md)；迭代计划模板见 `complex-task-planning` |

一次性产物指为特定目的写作一次、随后随 Git 历史留存的文档；内容过期时重写或作废。
用户指定保存路径时以用户路径为准。

## 模块文档

模块文档维护模块的定位、边界、契约、关键入口与当前事实；深层机制和长示例下沉到同目录主题文档。
小模块使用 `module-<模块>.md`；大模块或达到 500 行时拆为 `<模块>/overview.md` 与主题文档，
overview 是唯一对外入口，并索引各主题文档。存量五章文档在触及时把"关键约束与坑"拆分为关键约束与环境坑两章。

入口章节沿用六章，信息不足的章节简述现状：

```text
一、定位与边界
二、设计与机制
三、迭代操作
四、关键约束
五、环境坑
六、已知缺陷与方向
```

各章按模板展开，写法要点：

- **定位与边界**：说明职责、目标目录和依赖边；同层直接依赖/被依赖各一行链接，跨层关系指架构总览。
- **设计与机制**：给当前设计摘要、API 契约与主题索引；深层机制以主题文档承载，操作与验证入口放第三章。
- **迭代操作**：给构建、运行、验证等常用操作与命令。
- **关键约束**：记录使用本模块必须遵守的设计约束——不变量、契约前置条件、线程与生命周期规则、容量与性能边界；
  每条写清约束内容、来源依据和违反后果，随代码演进同步更新。依赖 API、协议本身的前置条件属于设计事实，记录在此或设计与机制。
- **环境坑**：记录环境因素带来的适用条件与处置，覆盖平台、驱动、SDK、编译器、进程锁、CWD、部署等；
  每条写清适用条件、症状、核查依据和处置方法。
- **已知缺陷与方向**：记录真实且尚未解决的缺陷、当前不支持的能力与远期方向；缺陷修复后从本章移除，
  相应机制沉淀到对应章节。

任务状态、决策与执行记录由 roadmap 维护（见 `development-workflow`），模块文档保持模块当前事实的视角。

## 设计文档与开发文档

两类均为一次性产物，面向人类读者，核心要求是易于人类理解：

- 叙述完整：给足背景、动机与推导过程，关键内容用完整段落陈述，读者单独阅读即可跟上。
- 信息充实：覆盖读者从零理解所需的背景、术语、依赖与示例，按理解顺序组织。
- 表达自然：以通顺陈述为主，列表与表格用于并列信息，保留必要的细节与特例说明。
- 落到代码：给出与代码现状的对应关系——模块、入口、锚点，便于读者定位验证。

设计文档围绕"为什么这样设计"组织：背景与目标、现状与差距、候选方案与权衡、选定方案、与代码的对应关系、风险与开放问题。
开发文档围绕"读者如何完成操作"组织：环境与前置条件、操作步骤、验证方法、常见问题处置。
两类文档中落定的机制、契约与标准操作结论同步进对应模块文档；文档本身作为记录随 Git 留存。

## 维护与引用

- 机制与契约只在所属模块文档维护；其他文档链接到权威入口，可附主题词。
  已拆分模块外部指 overview，主题由入口索引。模块拆分和迁移同步架构、README、技能与调用方引用。
- 模块文档与代码保持一致：API、格式或构建行为变化时同步对应设计摘要与主题文档，保留当前有效的约束与缺陷记录。
- 工具经验写相应 skill 的 references；常用短命令和主流程随 SKILL.md，模板及长操作资料按需加载。
  gameplay-dev 的消费者手册保持整包交付的自包含内容。
- 交付前检查目录、相对链接、索引与事实一致性；纯文档修改检查内容与引用后直接交付。
