# 图形异常排查方法

职责：先用抓帧明确异常阶段和异常点，再读相关代码与 shader 确定修改；修复与复验按用户授权执行。
先从架构入口定位模块并读取相关契约，再用抓帧锁定源码阅读范围，把执行证据作为结论依据。
用户要求只读时，探查文档、源码与已有证据，并按实际授权决定是否构建或修改 shader 探针。

## 标准排查顺序

1. **先抓帧，定位异常阶段**：按架构入口 → 相关模块文档了解必要契约；完成复现、工具环境、构建与
   导入产物的最少准备后抓帧。构建及已知长耗时操作后台运行。
   先看最终画面，再看各阶段附件，找出异常首次出现的阶段；先辨认目标 view、离屏目标与呈现图。
   围绕疑点按需读取相关模块文档、源码或阶段清单。
2. **在帧内明确异常点**：围绕可疑阶段检查 DC（drawcall）、输入输出资源、绑定和管线状态；
   按问题使用像素历史、几何检查、数值采样、shader 单步等手段，明确哪个事件、资源、状态或计算环节异常。
   把工具展示的 shader 源码映射和单步作为这一步的执行证据，围绕已锁定范围阅读工程源码。
   工具能力不足时记录缺口，选择可用的取证手段，并停止重复调用已确认不支持的功能。
3. **再读相关代码与 shader，确定修改**：带着已锁定的异常点，阅读对应实现、shader 或资产，解释证据并确定修法；
   用帧内证据回答“这一帧实际执行了什么”。
   需要修改 shader 插入探针时，先有具体疑点且现有帧内工具不足；只为该验证做最小阅读与改动，
   说明要测的量、预期结果和工具缺口。探针作为状态检查或单步的补充，按疑点决定启用时机。
4. **修改后重新抓帧验证**：按正常出口构建、导入变更，以可比较的场景与状态重抓，核对异常点及最终表现。
   移除临时探针后复验正式产物；行为中性要求另做逐帧精确对比。
   保存证据并回收本会话拉起的引擎、抓帧与分析进程。

日志、资产和产物新鲜度检查随疑点补充，并与帧内定位结合。一个 capture 可含多个 view 的独立图；
从呈现图或附件写入历史追踪，记录 view、尺寸、event 和资源；跨 capture 比较时重新核对 DC 与资源标识。
呈现图可能仅有 UI，场景在离屏图；阶段缺失时结合门控、零批、图裁剪和输入判断。
shader 沿 draw 实际绑定追踪，内置源与产物路径查现有注册表入口并复用其数据。

## 证据与结论

- **画面观察可以定位**：抓帧工具展示的最终画面和中间附件可支持定性判断，如“轮廓首次在光照阶段消失”。
  记录 capture、帧号、event/资源及截图，区分观察、假说与已证实原因。
- **精确结论要机器验证**：“逐像素相同”、具体数值、比例和误差等结论使用采样、状态读数或脚本比较结果。
  跨帧/跨轮比较先确认场景、动画相位、视图和产物可比；同帧号仍需核对状态一致。
- **使用可信出图与读数出口**：工具截图/纹理查看器用于看形态，采样或已验证的附件读取脚本用于读值；
  注意格式、通道、色彩空间和事件时点，用与工具能力匹配的读数定案。
- **按证据归因**：把 capture、状态、读数和对比结果保存到 `temp/`。遇到 replay 分歧、陈旧快照或
  与工具已知限制冲突的结果时，先核查证据可靠性，按需交叉验证，用本次证据确定根因。
- **把只读查询与修改探针分开**：replay 采样、buffer 查询、像素历史属于帧内检查；将中间量写入 RT 的
  shader 探针会改变程序，结论标注实验条件，并说明其与原始帧执行事实的区别。

## 知识沉淀

- 多轮排查使用[共享排查模板](references/investigation-template.md)，平台帧号与格式查对应工具资料。
  实际观察写清工具版本、提交/产物、工程/视图、capture/帧/event/资源和证据，模块机制链接所属文档。
- 把新事实、被证伪方向和复验结果写入[经验资料](references/experience.md)；工具命令和平台坑更新对应
  工具资料。按适用条件归档，并保留历史事实与出处。
- 日常维护 references；职责、步骤和证据标准在用户明确要求时调整。
