# 图形开发 debug 方法论

职责：先用抓帧明确异常阶段和异常点，再读相关代码与 shader 确定修改。工具操作按平台使用
`renderdoc-debug`（Windows）或 `gfxrecon-debug`（macOS）；最终帧精确对比使用 `acceptance-verify`。
先从架构入口定位模块并读取相关契约，再以抓帧锁定源码阅读范围；不以静态猜测替代执行证据。
用户要求只读时仅探查文档、源码与已有证据，不构建或修改 shader 探针；修复与复验按实际授权执行。

## 标准排查顺序

1. **先抓帧，定位异常阶段**：架构入口 → 相关模块文档，了解必要契约；完成复现、工具环境、构建与
   导入产物的最少准备后抓帧。构建及已知长耗时操作后台运行。
   先看最终画面，再看各阶段附件，找出异常首次出现的阶段；先辨认目标 view、离屏目标与呈现图。
   不要求通读无关模块文档、源码或预先建立完整阶段清单。
2. **在帧内明确异常点**：围绕可疑阶段检查 DC（drawcall）、输入输出资源、绑定和管线状态，
   按问题使用像素历史、几何检查、数值采样、shader 单步等手段，明确哪个事件/资源/状态或计算环节异常。
   工具展示的 shader 源码映射和单步属于这一步的执行证据；不转而通读未锁定的工程源码猜运行状态。
   工具能力不足时记录缺口，选择可用的取证手段，不反复调用已确认不支持的功能。
3. **再读相关代码与 shader，确定修改**：带着已锁定的异常点，阅读对应实现、shader 或资产，解释
   证据并确定修法；静态代码只能说明机制和可能原因，不能代替“这一帧实际执行了什么”的证据。
   需要修改 shader 插入探针时，须已有具体疑点且现有帧内工具不足；只为该验证做最小阅读与改动，
   说明要测的量、预期结果和工具缺口。探针是补充，不强制先于状态检查或单步。
4. **修改后重新抓帧验证**：按正常出口构建、导入变更，以可比较的场景与状态重抓，核对异常点及最终
   表现。移除临时探针再验正式产物；行为中性要求另用 `acceptance-verify` 做精确对比。
   保存证据并回收本会话拉起的引擎、抓帧与分析进程。

日志、资产和产物新鲜度检查随疑点补充，不替代帧内定位。一个 capture 可含多个 view 的独立图；
从呈现图/附件写入历史追踪，记录 view、尺寸、event 和资源，不跨 capture 照抄 DC 或资源 ID。
呈现图可能仅有 UI，场景在离屏图；阶段缺失须结合门控、零批、图裁剪和输入判断。
正式阶段编排查 [Rendering](../../../docs/modules/module-rendering.md)，依赖/屏障查 [RenderGraph](../../../docs/modules/module-render-graph.md)。
shader 沿 draw 实际绑定追踪，内置源与产物路径查 BuiltinShaderRegistry，不另复制注册表。

## 证据与结论

- **画面观察可以定位**：抓帧工具展示的最终画面和中间附件可支持定性判断，如“轮廓首次在光照阶段
  消失”。记录 capture、帧号、event/资源及截图，区分观察、假说与已证实原因。
- **精确结论要机器验证**：“逐像素相同”、具体数值、比例和误差等结论必须有采样、状态读数或脚本
  比较结果。跨帧/跨轮比较先确认场景、动画相位、视图和产物可比；同帧号不自动保证同状态。
- **使用可信出图与读数出口**：工具截图/纹理查看器用于看形态，采样或已验证的附件读取脚本用于读值；
  不临场自行解析 framebuffer 字节或用未经核对的图片转换结果定案。注意格式、通道、色彩空间和事件时点。
- **按证据归因**：保存 `temp/` 下的 capture、状态、读数和对比结果。遇到 replay 分歧、陈旧快照或
  与工具已知限制冲突的结果时，先核查证据可靠性，按需交叉验证，不把历史案例直接套成本次根因。
- **只读查询与修改探针分开**：replay 采样、buffer 查询、像素历史等属于帧内检查；将中间量写入 RT 的
  shader 探针会改变程序，结论须标注实验条件，不能作为原始帧的执行事实。

## 知识沉淀

- 多轮排查用[共享排查模板](references/investigation-template.md)，平台帧号/格式查对应工具资料。
  实际观察写清工具版本、提交/产物、工程/视图、capture/帧/event/资源和证据，模块机制只链接所属文档。
- 新事实、被证伪方向和复验结果写入 [经验资料](references/experience.md)；工具命令和平台坑更新对应
  工具 reference。保留历史事实与适用条件，不自动升格为通用规则。
- 日常只维护 references；本 skill 的职责、步骤和证据标准仅在用户明确要求时调整。
