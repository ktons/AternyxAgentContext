# 图形 debug 操作经验

记录可复用的操作经验：适用环境、工具版本、构建/提交与证据；重复条目合并，被证伪条目补更正与出处。
现行排查顺序与证据标准见 [方法论](../SKILL.md)。

## 记录格式

- 现象与触发条件：<画面表现、场景/视图、复现步骤>
- 工具与版本：<抓帧/采样工具、后端、驱动>
- 证据：<capture、帧号、event/资源、读数>
- 适用边界：<该结论成立的条件，以及可迁移的范围>
- 处置与验证：<修法、复验口径、结果>

## 出图与精确读值

- 浮点附件经系统看图工具转换可能产生假色（例如暖白显示为青色）。工具出图用于看形态；
  读值时核对格式、通道与转换链路。目测“逐像素相同”可能被脚本证伪：统计上 100% 字节不同、整体亮度
  差约 13%。定性定位与精确一致性使用不同证据。
- RGBA16F 中间 RT 导出 8bit PNG 后无法反推浮点原值。光影 capture 中某通道目测“大片 1.0”，
  96 点网格采样实际为 0.64–0.76 的连续渐变；8bit 量化与色彩映射会改变分布。
  结论：判断原值用浮点附件采样或状态读数，PNG 用于看形态。

## 映射内存与 buffer 快照

- 部分工具对持久映射内存的逐帧 CPU 写入只保留陈旧 buffer 快照，单凭 dump 推断“参数不在绑定里”会失真。
  按工具能力选择可靠读值，shader 探针用于补具体工具缺口。
- 另一类工具对 coherent 映射写入有完整记录：在已验证 capture 中，预览 hex、buffer 数据与探针三路逐位一致，
  视图矩阵行符合语义。新 capture 仍需核对工具版本、布局、事件时点和读数可靠性。

## 运行态与资产侧异常

- 批模式换场景会触发世界原点平移与重序列化复位；跨世界寻址态（世界空间 UV、页寻址 origin）需要重新核对。
  恒定单色且光照/几何正常时，按页 UV 出域和采样面失联排查；用引擎事件日志与资产就绪事件流定位断点。
  该结论适用于特定解析门控，迁移到其他恒定单色场景前先核对机制。
- 帧内证据锁定输入/几何疑点后，核对源资产语义与索引。OBJ 案例中法线块与面行引用错位会使法线全水平，
  ndotl=0、diffuse 全灭，只剩 ambient，表现近似光照或阴影失效。修复后以直射亮度、影子内 ambient 和
  最终画面复验。该结论适用于特定资产，迁移前核对资产语义。
- 源资产或 shader 修复后，经正常导入出口更新运行时产物；用导入/构建日志、产物时间与提交状态核对新鲜度。
  运行时产物未更新时，画面仍表现为修复前状态。
