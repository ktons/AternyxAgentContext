# Windows 崩溃取证与修复

职责：取得可复现、可符号化的崩溃现场并定位根因；修复按用户授权范围执行。模块机制归对应文档，
从架构入口定位模块。通用开发调度按工作区规则推进，执行已有 roadmap 时使用 `development-workflow`。

## 标准路径

1. 保留复现命令、CWD、退出码、最后日志和构建状态，暂停当前功能实现。
2. 先查项目 `temp/crash` 的 meta 和 minidump；有现场先离线分析，无现场或挂死时活体复现。
3. 发现实际调试器和符号，优先 cdb 原生 PDB，必要时用 lldb。核对 dump、exe 与符号的版本匹配；
   分析已有现场时按原构建取符号。获修复授权后后台构建受影响目标，用当前实现复现；
   编译器环境按项目入口发现。用户要求只读时，探查文档、源码与已有现场。
4. 用调试器批处理取异常上下文与调用栈，给运行窗口和超时；abort 类先下 CRT 断点，抢在弹窗阻塞之前取栈。
   定位真实调用链与生命周期，并把栈顶位置作为线索而非结论。
5. 获修复授权后向前修复，保留用户及任务已有改动；陈旧 obj/头依赖、锁文件等先核实环境证据。
6. 修复后重验原复现与受影响测试；仅排查时交付原因、证据与修复建议。收尾确认调试器与目标均退出。

## 常用命令

Windows PowerShell，从仓库根执行。先发现工具路径，dump、exe 与符号对应同一构建；离线分析使用现有构建：

```powershell
& "<实际cdb.exe>" -z "<minidump绝对路径>" -c ".ecxr; k; q"
```

lldb 活体复现由调用方设置实际 CWD 和外层总超时，条件式命令与脚本限制见操作参考；参数语义以实测为准。
