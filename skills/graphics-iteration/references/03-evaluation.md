# 判读口径与验收

窗口数值是当前 lookdev 编排下的**标定目标**，按场景与编排分别标定；换场景/编排/后处理口径后重新标定，
达不到时登记偏差并在报告中写明原因。

> 窗口、权重与色板阈值的**单一真源是 design tokens**（`lookdev.window.*` / `lookdev.weight.*`，
> 见[设计 token](06-design-tokens.md)）。本册记录这些值的来源、标定过程与例外条款；token 与本册冲突时
> 以 token 为准，并同步本册。复合分（`score_trial.py`）把窗口折成搜索目标，艺术阈值仍由 token 定义。

## 一、ROI 与指标定义

- **ROI** 按部位或机位定义，坐标以基准分辨率登记，其他分辨率等比缩放；天空掩码与近黑排除写进口径。
- **tone**：`luma.p15/p50/p98`、`luma.p98_over_p15`、暗部 RGB 均值与色序（`R>G>B` 计数）、
  `clip_frac`（任一通道 ≥250 的像素占比）。
- **face**：`shadow_coverage` = ROI 内 luma<0.7 占比（排除天空与近黑）；`face_lr` = 左右光向同 ROI
  逐像素通道最大差的 mean 与 >8 占比。
- **close-up**：全帧非天空掩码的 p15/p50/p98 + 中心区域暗部占比 + 主体包围盒高度占比。
- **luma** = `0.2126r + 0.7152g + 0.0722b`（sRGB 值域 0..1）；分位按 ROI 内有效像素统计。
- 判读前确认 `eval_metrics.json` 的 `metric_definitions` 与当前脚本一致；口径变化后的旧数字只作参考。

**贴图通道审计**（缺数据或怀疑通道语义时先做）：

- 逐通道统计（p50/std/通道间相关性）+ 单通道在屏探针出图，确认每个通道在模型上的含义；
  缩略图与旧注释只作线索。
- 审计时把每个通道的极值、分布、消费点与是否可用写成通道表，再进入 shading。
- 打包格式与导入设置一起核对：normal 贴图按打包约定保持通道完整，选择导入格式时确认目标通道保留。
- 审计结论为无可用通道时，回退关闭对应效果并记录原因。

## 二、亮度窗

- 每个 profile/group 在 token 中登记成对窗口，窗值由基线帧观测得到，并保留来源说明。
- **日景**：亮部 p98 与暗部 p15 分别落窗，暖色序 `R>G>B`；行内比 `p98/p15` 作为结构指标。
- **夜景**：亮部与暗部下限按夜景主秀光与低环境光重新标定；行内比作为观察项。
- **例外与限制**：
  - 窄坡 SDF 的 face/skinback 行内比受暗部色深影响，按方向性判据 + 亮暗各自落点窗验收。
  - LUT 内禀对比度与 p15 窗冲突时，登记“不可达”原因，以 p98 落窗、对比度提升与暗部色相为准。
  - `face_lr` 与 `shadow_coverage` 在小面积材质或描边暗线上会失真，单项覆盖数字作观察项，
    按方向性判据与亮暗窗判。
- 暗部结构用色序辅助；不同 profile 的窗值分别登记，跨 profile 比较前核对曝光口径。

## 三、光向与方向性判读

- **同行互镜像**：同机位 left/right 两张的左右半区亮度比互镜像且方向相反；镜像关系异常时核对灯位与相机键。
- **行内趋势**：正面机位行 front 最亮、back 最暗（逆光入影）；背面机位行 back 最亮（背部受光）；
  背面机位看武器时，back 才是照到可见面的灯（属于机位几何）。
- **换边**：左右光向的阴影换到相反半脸/半身；两边同时变暗时核对灯位与遮罩。
- 掩码与半区统计写明是否排除天空与近黑；不同掩码口径的数字分开比较。

## 四、中性门

改动只应影响目标区域，其余区域用可复现证据证明不变。按改动面选门：

| 改动面 | 中性门 |
|---|---|
| 新增材质槽/参数 | 参数置中性值时与改前逐 leg sha 相同 |
| shader 新分支 | 关闭分支的专项材质与基线 ROI 逐像素 sha 相同 |
| 后处理/描边/地面 | 中性面判 shading，成片面单独判 beauty；角色像素 ROI sha 不变 |
| 引擎 pass/绑定变更 | 稳态帧与 DebugId 帧逐字节一致；帧对拍全 IDENTICAL |
| 全量行为中性 | 改前/改后同参数采集，逐 seq IDENTICAL |

- 逐字节相同用 `sha256`（解码后裸像素或 ROI 裁剪字节），PNG 文件字节只用于冻结自检。
- “只加槽位不加代码”的改动同样跑中性门；FMA 收缩等 1/255 的 1–4 px 差如实记录并解释。
- 中性门不过时先查：二进制是否重建、资产是否重导、是否采到冻帧、两轮是否同 `--post`。

## 五、验收分级

| 级别 | 条件 |
|---|---|
| pass | 硬门通过、全部窗口内，人工判读确认画面符合目标 |
| conditional | 硬门通过、指标在窗内但存在需人工复核的风格/构图项 |
| fail | 硬门失败、窗口超限、出现冻结/空帧，或人工判读否决 |

- 效果验收 = 固定口径出图 + 人工与量化判读；golden diff 用于 agent 正确性、行为中性与回归拦截。
  两类门分开记录，验收报告写明本轮使用的类别。
- 复合分用于排序与搜索：`score=0` 表示窗口内；色板/构图/接触影由固定口径出图与人工判读验收。
  搜索最优经复验与人工判读后才进入验收。
- 效果证据走 `temp/` 的 PNG/JSON 与人工目检；新增 lookdev 基线在描述中标明用途。

## 六、基线接管与重采

- 图形域定帧基线由项目测试入口接管：feature 判别场景 × 集中基线库（manifest + PNG 双入库，
  判定权威为解码后裸像素 sha256）；工程定位、场景矩阵与重采政策以该项目 README 为准。
- 旧基线只读保留，新基线按新口径入库；两代 manifest 各有消费方，图形域新增走当前测试入口。
- **重采走显式例外流程**：采集与入库分步，附 `--reason` 凭据；报告与变更说明先评审，再连同
  manifest 与新 PNG 一并提交。跨工程重采先取得明确授权。

## 七、单轮判读 checklist

1. 基线目录存在且与当前二进制/资产同版本；`--post` 与分辨率记录在 `eval_metrics.json`；
   token 文件 `design_tokens.py lint` 通过且与基线同版本。
2. 本轮只改了一个变量；A/B 的参数与落点写进轮次记录（计划值与实测值分开）。搜索轮另记
   spec/seed/budget 与 train/holdout 划分。
3. `compare_evals.py` 看：缺 leg、clip 非零、p98 超限、最差 Δp98；再看 contact sheet 与关键特写。
   `score_trial.py` 看：`score`、`hard_failures`、罚分落在哪些 leg/指标。
4. 中性门：目标区域外逐字节相同，或差异逐项归因（FMA/描边/地面等）。
5. 不可达目标登记原因与替代判据，保留窗口与断言。
6. 收口：机制进模块文档、操作进本 skill、证据留 `temp/`、一次性脚本删除。
