# 开发计划与开发文档

把“改什么、怎么改、怎么验”写成一份可以照着执行的开发文档。

本 skill 独立调用：不要求已有设计文档或 roadmap，读者只读本文即可接手实现。
落位、文件名、生命周期与通用写法见 `documentation-writing`，本文只规定开发文档的流程与必含内容。

## 流程

1. **确认目标**：目标行为、非目标与边界；有歧义先向用户确认。
2. **勘察现状**：按架构总览 → 模块文档 → 必要源码的顺序读，定位相关模块、入口、数据结构与调用链，
   记录 `path:line` 与符号名；不靠通读源码重推已有设计。
3. **定方案与决策**：定稿实现形状——数据归属、控制流与生命周期、接口契约、依赖方向；
   关键取舍逐条写清选了什么、为什么、放弃了哪些候选、代价与影响面是什么。
4. **定改动落点**：列出将被改的文件、符号与新增位置，标出可照抄的现有先例；
   不确定的先读代码确认，不写“大概在某个模块”。
5. **排步骤**：按可独立验证的增量排序，写清每步改什么、为什么这个顺序、做完后系统处于什么状态；
   依赖顺序、并行边界与相邻改动的冲突点写明。
6. **定验收与回退**：每步给可复制命令、预期输出或观察点；不可逆改动给回退方式；
   当前环境无法验证的项注明依据与替代判据。
7. **落文档**：按模板章节写，缺信息就补勘察，不把问题留给执行者猜。

## 文档结构（按模板六节，必含）

1. 背景与目标：现状与触发原因、做完是什么样、非目标与范围边界。
2. 改动落点：入口、数据结构与调用链的 `path:line` 与符号名，注明代码快照。
3. 实现方案与关键决策：定稿形状，逐条写清决策、放弃的候选、代价与影响面。
4. 实施步骤：顺序、每步范围、完成后的系统状态、步骤间依赖。
5. 验收与验证：可复制命令与预期输出；行为中性或回归敏感改动写清比什么、怎么比。
6. 风险与回退：影响面、触发条件、回退手段与无法验证项。

## 边界

- 独立成篇：不引用设计文档、roadmap 与迭代文档；需要方案论证就在本文补理由，不要求读者跳转。
- 不写任务状态与执行记录，那是 roadmap 的事；不写每阶段验收表，那是迭代文档的事。
- 本 skill 与 roadmap 规划时附带的开发文档同一规格：同一模板、同一必含项，不因触发方式不同而缩水。
- 模板见[开发文档模板](../documentation-writing/templates/dev-doc.md)。
