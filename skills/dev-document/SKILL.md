# 开发计划与开发文档

把“改什么、怎么改、怎么验”写成一份可以照着执行的开发文档。

本 skill 独立调用：不要求已有设计文档或 roadmap，读者只读本文即可接手实现。
本文只规定流程与边界；章节、每节内容与写法见模板。

## 流程

1. **确认目标**：目标行为、非目标与边界；有歧义先向用户确认。
2. **勘察现状**：定位入口、数据结构与调用链，按模板第二节记锚点与可照抄的先例。
3. **定方案**：按模板第三节定稿实现形状与关键决策，写清选了什么、放弃了什么、代价是什么。
4. **排步骤与验收**：按模板第四至六节给增量、每步完成态、验收与回退。
5. **落文档**：按模板写全，缺信息就补勘察，不把问题留给执行者猜。

## 边界

- 不写任务状态与执行记录，那是 roadmap 的事；不写每阶段验收表，那是迭代文档的事。
- 与 roadmap 规划时附带的开发文档同一模板、同一必含项，不因触发方式不同而缩水。
- 模板见[开发文档模板](../documentation-writing/templates/dev-doc.md)，落位与通用写法见 `documentation-writing`。
