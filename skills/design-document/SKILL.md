# 方案设计与设计文档

先定义问题，再调研同类成熟实现，最后收敛到推荐方案；产出是一份自包含的设计文档。

本 skill 独立调用：不要求已有开发文档或 roadmap，也不替用户排任务。
本文只规定流程与边界；章节、每节内容与写法见模板。

## 流程

1. **定义问题**：目标、约束、成功标准与影响面；歧义先向用户确认，不替用户假设。
2. **调研**：按模板第三节查证同类成熟实现，记录出处与依据；不编造调研结论。
3. **收敛**：按模板第四、五节比较候选并落定推荐；不留“两个都可以”这类没有结论的收尾。
4. **落文档**：按模板七节写全；信息不足的章节标“待确认”，并在会话说明。

## 边界

- 实施步骤、文件级改动清单与验收属开发文档，本文不写；改动面只到模块与入口级。
- 模板见[设计文档模板](../documentation-writing/templates/design-doc.md)，落位与通用写法见 `documentation-writing`。
