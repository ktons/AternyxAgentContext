# 派发与交接示例

主 agent 按实际任务裁剪，已知信息内联。

```text
【任务】目标行为、改动边界、完成条件与 roadmap 任务 ID。
【约束】用户已确定的方案、接口/生命周期/分层约束、需要衔接的相邻任务产出。
【入口】相关模块文档、必要文件/符号/行号、现有先例、目标目录、构建目标与测试入口。
【现状】分支、已有改动归属、上轮完成部分、已验证事实与未解决问题。
【验证】受影响构建与测试命令；必要行为级证据。纯文档任务使用引用与一致性检查。
【协作】只做本任务；Git 由主 agent 统一提交；共享构建和运行实例由主 agent 调度；自起进程收尾时确认退出。
【回报】变更摘要、文件清单、验证命令与关键输出、遗留与设计偏差，通常不超过 40 行。
```

大任务拆成可独立编译验收的增量。单轮以约 40 分钟实现工作量作拆分参考；实现中及时增量编译，
保持每个增量处于已验证状态。只读勘察提供事实与 file:line，主 agent 据此形成任务说明。

## 中断交接

记录到 `.agents/docs/temp/handoff-<主题>.md` 或当前 roadmap 任务备注（交接单随任务收口清理）：

1. 分支与 HEAD、`git status --short` / `git diff --stat` 快照、相关证据文件路径。
2. 已完成且已验证部分；当前文件完成度与尚未通过的检查。
3. 卡点、精确复现命令/CWD/退出码、尝试及失败原因。
4. 建议下一步、仍需决策的问题、进程回收状态。

新 agent 从当前工作区审计并继续。
